# Орнату, маршруттар және қауіпсіздік

## 1. Орнату және іске қосу

| Қадам | Windows | Linux / macOS |
|---|---|---|
| Виртуалды орта | `python -m venv .venv` | `python3 -m venv .venv` |
| Белсендіру | `.venv\Scripts\activate` | `source .venv/bin/activate` |
| Тәуелділіктер | `pip install -r requirements.txt` | сол сияқты |
| Іске қосу | `flask --app app.web run` | сол сияқты |
| Телефон үшін | `run_phone.bat` | `python run.py --lan` |
| Тесттер | `pytest` | сол сияқты |

Талаптар: Python 3.10+, Flask 3, segno (QR-код). Дерекқор `instance/dekanat.db` алғаш іске қосқанда өзі жасалады; ескі нұсқаның дерекқоры автоматты түрде жаңартылады.

## 2. Серверге орналастыру
- Windows: `waitress-serve --listen=0.0.0.0:8000 wsgi:app`
- Linux: `gunicorn -w 1 -b 0.0.0.0:8000 wsgi:app` (SQLite болғандықтан бір процесс), алдына nginx + HTTPS.
- Орта айнымалылары: `SECRET_KEY` (кездейсоқ ұзын мән), `QUEUE_DEMO=0`, `COOKIE_SECURE=1`.
- Жөндеу режимі (`FLASK_DEBUG`) өндірісте өшірулі.

## 4. Қауіпсіздік тізімі

| Тексеру | Іске асыру | Тексерілді |
|---|---|---|
| SQL-инъекция | Барлық сұрау параметрлі (`?`) | test_sql_injection_is_harmless |
| Құпиясөздер | werkzeug `generate_password_hash`, ашық мәтін сақталмайды | test_passwords_are_hashed |
| CSRF | Әр POST формасында токен; JSON сұрауларда `X-CSRF-Token` | test_csrf_protection, test_chat_requires_csrf |
| XSS | Jinja2 автоэкрандауы, JS-те тек `textContent`, CSP `script-src 'self'` | test_xss_is_escaped |
| Рөлдер | `role_required` + db.py ішінде `can_manage_user` тексерісі | test_role_access, test_deputy_cannot_touch_dean |
| Бұғатталған пайдаланушы | Әр сұрауда `is_active` тексеріледі | test_blocked_user_session_is_dropped |
| Брутфорс және спам | Кіру — минутына 10, талон — 5, чат — 30 (IP бойынша) | test_login_rate_limit, test_chat_rate_limit |
| Ашық редирект | `safe_next()` тек ішкі жолдарды қабылдайды | test_open_redirect_blocked |
| Clickjacking | `X-Frame-Options: DENY` | test_security_headers |
| Сессия | HttpOnly, SameSite=Lax, кіргенде сессия жаңартылады | — |
| SECRET_KEY | Орта айнымалысынан немесе `instance/` ішіндегі кездейсоқ файлдан | — |
| Құпия деректер | Репозиторийде құпиясөздер мен кілттер жоқ (`instance/` .gitignore-да) | — |

**Рөлдер иерархиясы:** администратор > декан (`dekanat`) > декан орынбасары (`deputy`) > студент. Декан мен орынбасар өзінен жоғары тұрған аккаунтты өзгерте алмайды және өзінен жоғары рөлді бере алмайды; декан өтінімін тек администратор растайды. Аты-жөнін профильде тек администратор өзі өзгертеді.
